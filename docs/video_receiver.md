# RMUL 图传接收

## 操作

选择 RMUL 并进入后自动监听已保存的图传配置；没有画面时显示完整监看待机画幅、
低对比参考网格与角标、大字 NO SIGNAL、实际等待/暂停/中断/故障状态和监听端点。
暂停、故障分别显示 VIDEO PAUSED、INPUT ERROR，不伪造帧率或信号强度。
参考画幅只用于待机视觉，不限定输入视频比例。右下 Esc 提示可点击打开客户端菜单。
收到可显示帧后占位及提示全部隐藏，断流清屏后自动恢复状态标识。
画面按原始宽高比（包括样本宽高比 SAR）居中，尽量铺满窗口，空余处留黑；不拉伸、不裁切。
窗口调整只改变画面显示区域，不改变 UI 档位。

Esc 打开/关闭客户端菜单，全屏下仍优先开菜单；F11 切换全屏。
菜单默认进入当前会话，左侧包含图传设置、显示设置和运行诊断；图传只是一个分区。
侧栏始终提供继续画面和返回欢迎页。菜单打开期间继续接收。
图传分区可保存并开始接收或停止接收；关闭菜单不停止图传，也不提交编辑草稿。
同次打开期间切换分类保留草稿，重新打开菜单恢复已保存配置。
返回欢迎页释放监听端口并清空画面；再次进入恢复配置并开始监听。
正常视频没有标题、状态栏、HUD 或其他常驻叠加 UI；详细错误在设置内显示。
客户端菜单采用浅色侧栏分类布局，图传分区包含实际会话摘要、监听表单、0/1 分段选择和主次动作。
显示分区修改已有 UI 三档和全屏偏好；诊断只展示当前可取得的运行信息。
所有控件使用独立 UI 档位，提供悬停与键盘焦点反馈；小窗口只滚动表单，底部操作始终可见。
RMUC 继续保留原占位页；本功能不启动 MQTT 或定义业务字段。

配置保存在 Qt `AppConfigLocation/video.ini`，整组验证、原子保存，写失败保留原会话。
文件损坏时整体回退默认显示值且禁止监听，用户重新保存后恢复。

| 配置 | 默认 | 范围与含义 |
| --- | --- | --- |
| address | 0.0.0.0 | 本机数字 IP；默认所有 IPv4 接口。不是发送端 IP，不解析域名、不加入组播 |
| port | 3334 | 整数 1–65535，官方监听端口 3334 |
| index_base | 0 | 0 或 1，必须匹配发送端；0 是工程初始选择，官方未规定 |

需要允许系统防火墙接收对应 UDP 入站数据；程序不会自动修改防火墙。

## 协议和工程策略

依据 [2027 协议 §2](protocol_2027.md)：8 字节大端头（uint16 帧号、uint16 分片号、
uint32 帧字节数），每包最大 1400 字节，负载最大 1392 字节；标准 HEVC 1080p60，无重传。
按完整 Annex B 访问单元交给 FFmpeg，不能将带头的数据报直接当裸 HEVC 或 MPEG-TS 播放。

下列限制是保护实时链路的工程策略，不声称官方规定：

- 每帧最多 2 MiB / 4096 分片，最多 4 帧同时组装；组帧期限为从首片起单调时钟 150 ms。
- 接受可变长度分片、乱序和相同重复；长度冲突、同序号不同内容、缺片、超时帧丢弃。
  连续分片序号与累计字节数同时满足才输出，绝不将部分帧送解码器。
- 16 位帧号按半区间比较处理回绕；已输出更晚帧后不回放旧帧。
- 单会话锁定首个有效候选来源的 IP + UDP 源端口，避免混帧；该来源停包 1 秒后重新锁定。
  来源或解码帧序列跳变后重建解码器，等待可解码关键帧。
- 一秒没有成功解码画面就清屏，不用旧画面冒充实时视频。收到码流但不能解码时错误留在设置。
- 系统 UDP 接收缓冲请求 8 MiB（实际由 OS 限制）；每轮最多处理 128 包，持续检查停止/超时。

这套策略需用官方发送设备核实分片起始序号、访问单元边界和关键帧恢复行为。

## 线程、缓存与渲染

`VideoReceiver` 由主程序持有，公开方法仅 GUI 线程调用。
一个接收线程拥有 QUdpSocket、VideoAssembler 和 HevcDecoder，全程不调用 GUI。
停止请求中断，最多等待当前包/解码完成后 join；socket 与 FFmpeg 资源在该线程退出时释放。
QML engine 先析构，再释放接收器，避免悬空绑定。

FFmpeg 软件 HEVC 解码最大 1920×1080，4 个 slice 线程，不启用增加帧排队的 frame threading。
像素先转换为 CPU `RGBA8888`（8 bit）；YUV 矩阵使用流中 BT.601/709/2020 标记，未标注 HD
使用 BT.709，区分有限/全范围。此基础路径不提供 HDR 色调映射。
显示只用最新帧，不按 PTS 排队；接收、超时以 QElapsedTimer 单调毫秒为准。
没有墙钟同步，不把到达时间声称为相机采集时间或端到端延迟。

跨线程单槽邮箱由互斥锁保护，只发布不可变 QImage，共享后不修改；GUI 每 16 ms 取最新帧，
无逐帧/逐包 queued signal 堆积。VideoView 在 Qt 场景图同步阶段上传纹理，纹理由节点持有，
只在新帧/重建节点时上传，窗口缩放只更新矩形。软件场景图也可运行。
用户态组帧最多 8 MiB，加单槽/GUI/纹理每张最大约 7.9 MiB；此外还包括 FFmpeg 参考帧、
解码线程、驱动与系统 socket 缓存，不能把这些数值当进程总内存上限。

## 构建和许可

正式链接 FFmpeg **7.x**：libavcodec 61 / libavutil 59 / libswscale 8，C API。
Windows 使用匹配工具链的 shared SDK，设置 `PIP_FFMPEG_ROOT` 为含 `include/lib/bin` 的前缀；
MinGW 需要 `.dll.a`，MSVC 需要对应 `.lib`。CMake 不会联网下载或引入厂商 SDK。
运行 DLL 优先 SDK，亦可使用当前 Qt kit 附带的同 ABI 版本，构建后复制到应用目录。
必须保证 SDK 头文件、导入库和 DLL 相匹配；发布时随附许可及对应源码获取方式。

Ubuntu 同样需要 FFmpeg 7 开发 SDK；通过 `PIP_FFMPEG_ROOT` 及 `CMAKE_PREFIX_PATH` 指定前缀。
发行版默认 FFmpeg 6/8 不能当作 7 的兼容替代；共享库通过系统安装或部署 RPATH 解析。
本轮没有 Ubuntu 可运行环境，不能声明已经完成 Ubuntu 构建或 X11/Wayland 验收。

本机开发使用 FFmpeg 官方 7.1 源码头文件和 Qt 6.9 随包的 FFmpeg 7 共享库，
由 MinGW gendef/dlltool 生成本地导入库，仅存于忽略的 `.cache/ffmpeg/sdk`；
libavutil/avconfig.h 的目标配置为 Windows x86_64 little endian / fast unaligned。
其他架构必须使用该架构正式生成的 SDK，不能复用此配置。
官方源码：[ffmpeg-7.1.tar.xz](https://ffmpeg.org/releases/ffmpeg-7.1.tar.xz)，
SHA256 `40973d44970dbc83ef302b0609f2e74982be2d85916dd2ee7472d30678a7abe6`。
项目只使用 FFmpeg 内置 HEVC 解码及 swscale，不链接本机测试编码器或 ffmpeg CLI。
FFmpeg 基础许可证 LGPL-2.1-or-later，启用 GPL 组件会改变发行许可，取决于实际构建配置；
许可文本随 `resources/licenses` 保留，分发时必须核对所选二进制的配置和合规材料。

## 预算与验证

目标为官方 1080p60；无缓冲累计、GUI 不做网络/解码是当前必须满足的结构约束。
计划实机验收目标：1080p60 连续 30 分钟，本机接收至显示 P95 小于 50 ms、应用新增丢帧率
低于 1%、GUI 交互 P95 小于 50 ms、CPU 平均低于 50%（记录总逻辑核数）、进程 RSS 低于
512 MiB 且无持续增长。端到端延迟还需相机/发送端时间同步或高帧率实拍测量。
这些是待测目标，当前 CPU 路径不承诺所有 Core i / Ultra 设备达标。

Windows 11 / Qt 6.9 / MinGW 13.1：完成真实 UDP 回环→组帧→HEVC 软件解码测试，覆盖
乱序、重复、丢片、非法包、超时、回绕、有界组帧、两种序号、来源隔离、端口冲突与恢复、
停止/重启、配置损坏和保存失败。离屏真实 QML 验证无图状态、16:9 画面在 16:10 窗口的黑边、
窗口变化后等比居中、Esc 菜单优先于全屏退出、停止清屏、返回释放会话。
空画面还验证首帧隐藏、断流恢复、暂停/故障与会话一致；设置验证最小窗口三档 UI、草稿取消、
非法端口禁用保存、分片选项应用和键盘关闭；菜单分类切换、显示档位修改及接收不中断均有交互回归。
官方接收端的设计调研见[设计参考](design/video_receiver_research.md)。
关闭图标为项目自绘 SVG，待机画幅由 Qt Quick 原生图元绘制，无新增运行依赖。

本轮验证基于 320×180 自产 HEVC 样本；尚未验收官方图传设备、1080p60 性能、长稳、DPI、
Windows 原生窗口实机或 Ubuntu。Intel/NVIDIA 硬解、零拷贝和 NPU 均未启用；当前 CPU
基础路径不依赖 NVIDIA，Qt 场景图负责跨平台渲染。硬件加速必须后续按设备探测和实机验证。
