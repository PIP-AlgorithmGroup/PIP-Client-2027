# 手动检查与安装更新

此功能在 `develop/p1ne4pp1e/manual-updates` 分支试用，尚未随 v0.4.0-rc.1 发布。
欢迎页“关于”和比赛 Esc 菜单“软件更新”共享同一状态；启动时不联网、不自动下载。
用户选择检查、下载，再确认“退出并安装更新”。比赛页可检查和下载，须返回欢迎页才能安装。

## 更新来源与渠道

使用公开仓库 `PIP-AlgorithmGroup/PIP-Client-2027` 的 GitHub Releases API。
不需要账户或内嵌令牌，不上传配置、设备或比赛数据。
按 SemVer 比较全部已读取发行的最高版本，忽略草稿与构建元数据；数字标识按数值排序，
例如 rc.2 早于 rc.10，rc 早于正式版。正式渠道不接收任何预发布，预发布渠道包含正式版。
当前程序版本带预发布后缀时默认包含预发布；用户选择保存到独立的 updates.ini。
每页 100 条、最多 10 页、每页正文最多 2 MiB；超过上限报错，不谎称已是最新版。

当前仅选择 Windows x86_64 Setup 或 Ubuntu amd64 DEB。新版缺包、摘要不完整、
网络失败、GitHub 限流或超时均可见，缺包时不静默退回旧版本。
发行说明按纯文本显示，不执行远端 Markdown/HTML 中的内容。

## 下载和安装交接

- Qt Network 异步请求，固定 HTTPS 来源与重定向域名，不忽略 TLS 错误。
- GitHub API 的附件名称、uploaded 状态、大小和 sha256 摘要全部校验。
  附件最多 2 GiB，默认无活动超时 15 秒，整次检查 60 秒、下载 10 分钟总时限。
- 文件写入用户缓存的专有临时目录；取消/失败不提交半包，允许重新下载。
  完整包流式计算 SHA-256，安装前再在后台复核，修改过的包不能安装。
- 独立 PIPUpdateHelper 复制到缓存，不从待覆盖目录加载 Qt/DLL。
  助手等待旧进程退出，最多 60 秒；超时不强杀、不执行安装。
- Windows 只识别固定 AppId 对应的当前用户安装目录，调用现有 Inno Setup 覆盖升级。
  不要求安装器关闭其他客户端实例；占用导致升级失败时恢复原程序。
- Ubuntu 只识别 `/opt/pip-client/bin/PIPClient` 的安装版，使用固定的
  `/usr/bin/pkexec /usr/bin/apt-get --yes --no-remove install <包路径>`，授权由系统提供。
  不通过 shell 拼接命令，不以 root 启动客户端，不创建常驻提权服务。
- 安装成功、失败或取消授权后均尝试以原用户重新启动客户端；固定结果文件在下次启动时显示。
  不清除用户设置与日志。完整下载保留在缓存供手动安装，取消/失败的临时文件在退出时清理。

便携 ZIP 和开发构建可检查、下载、打开下载位置；不直接覆盖其文件。
本分支需要先手动安装一次包含更新助手的发行包，之后才能试用安装版的自动交接。
Linux 需有 polkit 授权代理和 apt，不能把普通用户应用直接写入系统目录当作升级方案。

## 验证与信任边界

离线测试使用环回 HTTP 服务覆盖版本、渠道、下载、重定向、损坏、超限、取消和重试，
测试入口不允许通过环境变量改写产品更新源。安装助手使用编译时隔离的测试目标和伪进程，
验证等待、成功/失败及重启，不调用实际 apt 或替换用户安装。
真实 GitHub 下载使用显式 `PIP_UPDATE_LIVE_TEST=1` 专项，不作为普通测试的外网依赖。
构建、UI 与平台验证结果见[更新验证](../validation/updates.md)。

当前以 HTTPS、官方仓库控制权和 GitHub API 摘要作为信任来源。
SHA-256 检查内容完整性，不等于独立的发布者签名；尚未实现签名更新清单、Windows
代码签名、断点续传、差分包、事务回滚、多实例协调或 APT 更新仓库。
助手失败时保留已下载包和系统安装器恢复入口；不承诺任意安装中断都能自动恢复旧版。
