# 垂直同步开关与验证记录

日期：2026-11-13。下文保留 Qt 6.9.0 的开关与长稳验收记录；项目与 CLion 主配置已迁移到 6.12.0。
后续已补做 Qt 6.12.0 独立构建、回归、部署及同机 A/B，见[6.12 实测](../qt612.md)。
官方源码差异及来源见[渲染等待研究](../../research/video/qt_render_wait.md)。

## 产品契约

- 欢迎页设置和 Esc → 显示设置共享同一个垂直同步偏好，默认开启。
- 保存后重启生效；运行中不重建窗口、不切换场景图，不重启视频或网络会话。
- `vertical_sync` 为本地 INI 布尔项，旧配置缺失时默认开启；非法值使整份偏好无效。
  保存失败不发布新值，开关重新绑定到已保存值；恢复默认重新请求开启。
- 启动先读取偏好，再在首个窗口创建前通过 `QSurfaceFormat` 请求 swap interval 1/0。
  请求一经应用便冻结；运行中重读配置或恢复默认只影响下次启动。
- `QSG_NO_VSYNC` 是外部覆盖；Qt 6.9 按变量存在性判断，值 `0` 仍会关闭。
  状态说明显示该覆盖，不在进程运行中修改环境变量。
- 启动请求不等于驱动或合成器实际采用的呈现模式；Wayland、X11、DWM 和驱动仍可能限制显示。
  `frameSwapped` 只用于 Qt 呈交观测，不代表屏幕像素已经亮起。

两平台采用相同公开 Qt API；未将 Windows 私有 DXGI 调度变量用作产品开关。
Qt 6.12 新增关闭同步窗口跳过 DXGI vblank 注册的路径，已在独立环境进行 A/B；
6.9 单独关闭同步仍可能保留 GUI 更新唤醒等待，不能承诺消除约 5ms。

## 验证环境与覆盖

Windows 11、Qt 6.9.0、MinGW 13.1、FFmpeg 7，Intel Core i7-14700HX、
NVIDIA GeForce RTX 4070 Laptop GPU；原生窗口使用 Direct3D 11。
原客户端和本地发送服务继续运行，本轮构建、原生回归及两路长稳也有并发。
这些是并发压力观测，不能用作独占吞吐或开/关同步的性能 A/B 基准。

| 范围 | 验证内容 |
| --- | --- |
| 配置控制层 | 默认与旧文件、非法布尔、原子写入失败、保存/重启、环境覆盖、恢复默认、重复读取和损坏配置修复后的启动快照冻结 |
| 设置组件 | 两入口共享、键盘操作、写失败恢复绑定、待重启说明；修改不改变窗口几何或当前请求 |
| 视频与叠层 | 画面等比、断流/重连、端口故障、停止/重配、独立叠层、呈交统计、设备选择 |
| 窗口生命周期 | 调整窗口、三档 UI、全屏往返、模式切换、最小化/隐藏/恢复、Esc 与焦点、反复创建销毁 |
| 长时间运行 | 1080p HEVC GOP 按 60Hz UDP 回环发送；每 30 秒记录接收/呈交快照和进程资源 |

Ubuntu 控制层使用 WSL Ubuntu 22.04、GCC 11.4、官方 Qt 6.9.0 真实构建运行。
设置组件直接加载产品 QML，采用 offscreen/software；这是 Linux 配置与交互验证，
不覆盖完整客户端依赖、原生 GPU、X11/Wayland 合成或 Linux 视频长稳。
全部临时依赖与工程仅存于忽略缓存，未安装系统包或引入新的产品依赖。

## 回归结果

| 环境 / 组合 | 结果 |
| --- | --- |
| Windows 完整 Debug 构建 | 通过，包含产品 QML 编译和 FFmpeg 运行库部署 |
| Windows 最终串行 CTest | 11/11 通过，153.27 秒；此前并发失败另行保留与解释 |
| 原生 D3D11，自动硬解，同步开启 / 关闭 | 各 66 项通过；记录的实际后端为 Direct3D 11 / D3D11VA，swap interval 分别为 1 / 0 |
| 原生 D3D11，CPU 解码，同步开启 / 关闭 | 各 66 项通过；开启组合曾在并发窗口干扰下动效未启动，独立完整复测通过 |
| Windows 软件渲染，CPU 解码，同步关闭 | 关键路径 11 项通过；软件后端不验证 GPU 的实际同步行为 |
| Ubuntu 配置控制层 | 25 项通过，无跳过 |
| Ubuntu 真实设置 QML | 最终 9 项通过，无跳过；六种启动/尺寸组合验证真实标签颜色，无 QML 警告 |
| 格式及静态检查 | clang-format、qmlformat 一致性、qmllint、差异空白检查通过 |

Linux 离屏插件不能真实切换系统暗色方案，该环境探测未计为产品通过。
组件显式使用浅色面板调色板，真实文本颜色断言通过；原生系统暗色环境仍未验收。
Windows 最小化/恢复测试曾出现 Qt `QPainter` 的无 paint engine 告警，未引发断言失败或崩溃；
该运行时告警尚未定位，不等同于 QML 静态检查告警，也不能标记为已消除。

初次 30 分钟测试被 QtTest 默认 300 秒函数超时中止，不能算长稳通过；
重跑设置 `QTEST_FUNCTION_TIMEOUT` 大于测试时长，并保留原失败日志。
原生窗口回归也暴露两处测试条件问题：只发两帧后截图/缩放触发正常断流清屏，
以及关闭同步的初始化已创建偏好文件而故障用例仍直接创建同名目录。
现已分别持续供帧、显式清理本用例临时文件，保留原生回归覆盖。
提前读取偏好造成的首次欢迎页焦点遗漏已修复，并添加无需手工强制焦点的首启断言。

并发 CTest 两次出现接收回归失败。首例将 UDP 绑定就绪误当作硬解已初始化，
固定 200ms 后的一次通知可能实际是队列失效清屏；已改为真实帧预热、限制首次合并通知数量，
并异步确认最新 HD 帧，不通过放大 sleep 掩盖问题。
第二例是乱序接收用例单帧未在断流失效前显示；没有证据能将其归因于同步开关。
两项隔离复测 5 项通过，原始失败保留；不把后续通过解释为所有高负载超时已修复。

## 关闭同步长稳观测

两路均通过产品保存偏好后以 swap interval 0 启动，未使用私有调度覆盖。
QtTest 的最终断言通过仅证明测试结束时输出恢复和生命周期可用，
以下全程快照暴露的异常仍必须单独判断。

| 项目 | 自动 D3D11VA，30 分钟 | CPU，20 分钟 |
| --- | --- | --- |
| 进程结束 | 正常，无崩溃；测试 3 项通过 | 正常，无崩溃；测试 3 项通过 |
| 30 秒诊断快照 | 59 次；2 次无有效 OUT，后续恢复 | 39 次；均有有效 OUT |
| 有效快照 OUT 范围 | 42–61 | 41–60 |
| 最终待解码 AU 累计丢弃 | 457 | 36 |
| private bytes 范围 | 483.3–554.3 MiB | 490.5–506.8 MiB |
| private bytes 首次 → 末次资源采样 | 532.0 → 546.4 MiB | 504.4 → 506.5 MiB |
| 句柄数范围 | 1249–1264 | 1124–1134 |
| 线程数范围 | 96–99 | 77–82 |
| 资源采样段平均 CPU 占用 | 约 1.54 个逻辑核 | 约 1.70 个逻辑核 |

资源监控分别覆盖约 1652 秒 / 1111 秒，晚于测试启动；不能据此判断启动前后的资源变化。
区间内未观察到内存或句柄持续无界增长，但有限时长采样不能证明没有泄漏。
本轮没有 GPU 显存、功耗或物理扫描数据。

硬解异常时仍收到约 59 帧/秒，解码/呈交无有效速率且队列丢弃跳增，随后无需手工操作恢复。
这支持继续定位解码/驱动或并发负载停顿，不能仅归因于 Qt 呈交或垂直同步。
期间系统日志未检出 Display / NVIDIA 驱动重置或休眠事件；无事件不等于驱动没有等待。
30 秒快照无法给出每次停顿的精确起止，也缺少同步开启的等负载对照。
因此本轮只接受“开关及故障恢复可用”，**尚不接受关闭同步的全程流畅性达标**，
不承诺满 60fps 或 low 帧改善；默认保持开启。

原始本机证据均归档在忽略的 `.cache/archive/flat/`：`vsync_off_gpu_30min.txt`、
`vsync_off_cpu_20min.txt` 及同名前缀的资源 CSV，四组合 `vsync_verified_*.txt`，
CPU 同步开启独立复测 `vsync_cpu_on_final.txt`；不提交机器专用日志。

## 可复现入口

先用项目正常 CMake 工程完整构建，保证 Qt、MQTT 和 FFmpeg 运行库可解析。
原生 Windows 回归使用 `QT_QPA_PLATFORM=windows`、`QSG_RHI_BACKEND=d3d11`，
分别组合 `PIP_UI_TEST_VERTICAL_SYNC=1/0` 与 `PIP_VIDEO_DECODER=auto/cpu` 执行
构建目录中的 `welcome_ui_test`。每组合必须为独立进程；测试专用变量通过产品 setter
保存偏好，再在建窗前应用，不以 `QSG_NO_VSYNC` 替代产品入口。

长稳只执行 `hdVideoReportsActualBackendAndPresentation`，设置：

| 测试变量 | 含义 |
| --- | --- |
| `PIP_VIDEO_TEST_STREAM` | 含 AUD、1920×1080 的 HEVC Annex B GOP 文件绝对路径 |
| `PIP_VIDEO_TEST_DURATION_MS` | 持续时间，毫秒；默认 2500，最大 1800000 |
| `QTEST_FUNCTION_TIMEOUT` | 必须比持续时间更长，30 分钟测试使用 1860000 毫秒 |

清除 `QSG_NO_VSYNC`、`QT_D3D_NO_VBLANK_THREAD`、`QT_QPA_UPDATE_IDLE_TIME`、
`QT_D3D_MAX_FRAME_LATENCY` 和 `QSG_RENDER_LOOP` 等外部实验覆盖。
保留 `VIDEO_STABILITY`、`VIDEO_MEASUREMENT` 及每 30 秒进程 CPU 累计、private bytes、
工作集、句柄数和线程数。快照中的阶段统计是最近一秒，不能将多个 P95 相加或平均为全程 P95。
本地测试帧源与时间戳定义见[分阶段测量](stage_measurement.md)。
