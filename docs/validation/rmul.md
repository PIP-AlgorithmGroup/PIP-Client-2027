# RMUL 正式界面实现

本轮将已确认的[视觉原型](../design/rmul/prototype/README.md)落到正式 Qt Quick 界面。
颜色、圆角和版式是项目方案；官方规范与字体资料的证据边界见[来源审查](../design/rmul/visual_reference_audit.md)。

## 页面与层次

- 无画面时只保留居中的视频缺失图标、中文真实状态、短说明和 Esc 菜单入口。
- 实况继续按原比例居中显示，保留黑边；不叠加 Logo、网格、端点或模式装饰。
- `businessOverlay` 与视频及视频占位同级，使用窗口逻辑坐标，内容仍为空。
- 图传接收、断流、暂停、错误和恢复不销毁或隐藏业务挂载层。
- 未来展示模型的最后有效值、新鲜度和身份隔离契约见[图传接收](../modules/video_receiver.md)。
  本轮没有实现业务字段或展示快照，也未改变 DataPipeline 失联清理和控制门控。

## 设置与自检工作区（2026-11-17）

正式界面采用评审选定的方案 A。原型已独立归档至
`develop/p1ne4pp1e/rmul-preflight-prototype`（`a4f07f9`），不进入产品资源或部署。
归档中的模拟连接、示例身份与浏览器输入没有移入正式客户端。

- 统一侧栏工作区跟随窗口扩大，只保留四周 12 逻辑像素留白；字体和控件仍遵循用户档位。
- 接入 MQTT、图传接收、自定义控制器、键鼠测试均可自由切换，失败不锁定其他项目。
  切页保留各自草稿，重开菜单恢复已保存配置；准备概览不阻止返回画面。
- 概览和宽窗口检查栏读取当前真实网卡、MQTT、图传和串口状态；没有模拟通过按钮。
  窄窗口保留原页状态与概览，避免结果栏压缩配置字段和完整键盘。
- 控制器可明确选择不使用，立即断开但保留参数；默认没有已保存端口时不使用。
  所有设置或交互页面暂停串口转发，本地解析与有效帧统计继续。
  返回画面时撤销旧发送通道、驱动积压与半帧，只恢复后续完整新帧的转发资格。
- 图传页将现有 VideoView 挂入预览容器，关闭或切页挂回比赛层，不新增接收或解码链路。
  比赛 HUD 在工作区隐藏；完整诊断保留于运行诊断分区。
- 键鼠测试保留 ANSI 104 完整物理布局、橙色按住与绿色已测标记；长键名按实际键帽边界缩小，
  不裁切或省略。鼠标响应与人工确认位于键盘下方，键盘内部可横向滚动。
- 开始测试、重新检查、保存与控制输出开关固定在底部；详细统计和图传协议规格默认收起。
  人工确认须先有实际键盘/鼠标事件，保存配置、出现采集错误、重新检查或离开比赛页会撤销确认。
  用户确认只代表其测试过的响应，不推断全部 104 键、USB 扫描率或机器人执行正常。

当前实现只使用既有 Qt 组件与打包图标，不增加依赖。图形/输入/设备实机结论仍按平台分别记录。

图传协议规格默认折叠；测试显式展开并完成布局后再滚动，验证最小窗口仍可访问末项。

另在 Windows 原生 Direct3D 11 窗口完成两项专项：完整键盘排列，以及实际 UDP→CPU HEVC→
预览→主画面的同一 VideoView 挂载与恢复。截图人工检查了真实预览、完整键盘、最小窗口大档导航，
没有把浏览器原型或模拟截图算作 Qt 验证。

Ubuntu 22.04 / Qt 6.12.0：正式客户端、UI/串口测试目标及 `all_qmllint` 构建通过。
相关 4 组 CTest 全部通过：welcome_ui、serial_controller、match_session、input_controller。

## 早期 ESC 菜单（历史验证）

统一使用中性灰、深灰文字与橙色强调；保留会话、图传、显示、诊断四个分区。
会话按接入网络、机器人身份和连接状态分组，网络采用两列；机器人先选红蓝再选兵种，
ID/clientID 只读，切换阵营清除兵种草稿。下拉为单向箭头，保留 Qt 键盘导航。
连接配置、图传可编辑字段与只读协议规格均沿用既有后端行为。

中档菜单最大 1120×740 逻辑像素，720p 为 1120×640，1080p 为 1120×740；
小中大档倍率仍为 0.9/1.0/1.1。窗口只改变布局和可用空间，字号不按窗口缩放。
会话与图传页在小窗口内部滚动，底部动作始终固定；关闭不提交草稿、不停止接收。
字体沿用已打包 Noto Sans SC，SVG 随应用打包，不引入新的运行依赖。

## 本地验证

环境为 Windows 11、Qt 6.9、MinGW 13.1，软件离屏渲染。

- 正式客户端和测试通过 CMake/Ninja 构建。
- 完整 CTest 为 7/7 通过，覆盖协议、MQTT、会话、视频、应用控制和 UI。
- QML 通过 qmlformat 一致性和 qmllint，C++ 通过项目 clang-format，差异通过空白检查。
- 完整 `welcome_ui_test` 文件报告为 60 项通过；故意缺失欢迎页图片的用例只接受预期告警。
- 保留真实 UDP→HEVC→VideoView 等比显示、黑边、停止/恢复、端口冲突等既有回归。
- 新增业务挂载层在首帧、超时、暂停、绑定失败、恢复和窗口变化后的对象/值/坐标保持检查。
- 新增最小窗口三档会话动作不随表单滚动检查。
- 1024×640、1280×720、1920×1080 × 三档，逐项切换四个菜单分区并检查边界。
  按需截图输出到被忽略目录，人工查看待机、会话、图传、显示和诊断布局。

复现截图：设置 `PIP_UI_CAPTURE_DIR` 为已存在的输出目录，以项目配置的 Qt 离屏环境运行
`welcome_ui_test rmulLayoutAcrossWindowsAndUiSizes`。
该用例不依赖截图生成执行边界断言，普通回归不会写入截图。

本轮未验证 Ubuntu、Windows 原生窗口交互、多屏、DPI、Intel/NVIDIA 驱动或实际赛场设备；
未测量 1080p60 长稳性能。改动只使用 Qt Quick/Qt Controls 和打包 SVG，不增加 GPU/NPU 依赖。
