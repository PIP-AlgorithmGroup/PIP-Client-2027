# 键鼠输入验证记录

日期：2026-11-16。主机为 Windows 11 / MinGW / Qt 6.12.0；
Ubuntu 22.04 为 WSL，Qt 同版 SDK，通用 UI 使用 offscreen/software，原生 Wayland 使用 WSLg。
这些结果不覆盖实体 Ubuntu 桌面、USB 设备硬件轮询率、官方裁判服务器、网络抖动或机器人执行延迟。

## 已执行验证

- `input_state`：多键同时松开、左右修饰键/多设备独立、恢复时抑制按住键、25ms 心跳失效清代、
  鼠标按交付计数、分数灵敏度余量、失败不推进水位、本地测试禁止控制、全零释放只一次、
  代次撤销禁止后续旧代写出、HUD 具体键名。
- `input_pipeline`：真实 Qt MQTT 和独立线程回环服务器；输入线程与 MQTT 在 GUI 阻塞 250ms 时继续运行，
  覆盖 200/75Hz、静止周期发送、完整按键释放、累计运动无重复、本地测试不发送、断线不依赖 GUI 撤销。
  初次 Windows 200/75Hz 阻塞段分别收到 45/18 帧；相位调度后一次样本为 46/17 帧。
  这仅证明进展独立，不证明每次系统调度均达到 200Hz 或 P99 延迟目标。
- `input_controller`：非法设置原子拒绝、临时目录保存/重载、无窗口不授予捕获。
- `welcome_ui`：完整 Main.qml 离线进入 ESC 测试页、保存灵敏度/频率、切换分区结束测试、
  按键/鼠标/MQTT 统计、HUD 键名、小窗口动作可达；新增分类后导航独立滚动，
  回归覆盖大中小 UI 档位。1024×640 截图已检查。
  追加锁定测试时 Tab 不改变 GUI 焦点、鼠标不切换菜单、Esc 可退出的事件隔离回归。
- Windows `native_input_probe` 初次专项通过：SendInput 三键同时松开、GUI 停止派发时原生鼠标交付继续、
  interrupt 后光标约束解除；不是 USB 硬件回报率测试。追加多次生命周期专项通过。
  后续追加窗口切换断言的复测未获得系统前台窗口，三次尝试后停止；诊断确认
  `GetForegroundWindow()` 与测试窗口不同，产品正确拒绝捕获。新增窗口切换专项仍待独占前台重验，
  不能用初次成功替代后续版本的完整原生验收。
- WSLg 原生 Wayland `nativeBackendStartsAndReleases`：三次创建/销毁独立输入队列及相对指针协议通过，
  未报 Qt proxy 所有权或释放错误；不据此宣称实体 Ubuntu 输入延迟和捕获已验收。
- Windows QML 静态检查通过；C++ 按项目格式检查。当前可用 clang-format 14，
  使用与项目等价的内联格式参数（其不识别较新版本的 `LineEnding` 字段）。

## 验证期间的问题

第一轮 Windows 并行默认硬解回归中，旧视频测试出现丢帧恢复超时；同一套 CPU 路径重跑通过。
新增导航分类使大号 UI 的菜单底部按钮超出最小窗口，已修正为导航滚动、底部动作固定，相关回归通过。
满载时输入源超过 25ms 未获调度，会触发中立释放；集成测试不再错误要求整个进程仅出现一次释放，
每一代只发送一次由确定性状态测试验证。没有放宽产品健康阈值或禁用测试。
完整 Windows 回归 22 组中一次旧视频 `low1Fps` 断言失败，未改产品或测试阈值，
单独重跑整组 `welcome_ui` 后通过（71 通过、2 跳过）；最终 Windows 完整 22 组 CTest 全部通过。
Ubuntu 完整构建及 21 组 CTest 全部通过；原生 GPU 用例的可见跳过不计作 GPU 验收。

## 待实机验收

Windows/Ubuntu 各以 125/500/1000Hz 实体鼠标、常用键盘和多设备测试捕获/失焦/热拔插/窗口恢复；
Ubuntu 分别覆盖原生 X11、原生 Wayland 和 XWayland，X11 evdev 键码映射及原生锁定必须确认。
Wayland 统计未加速相对事件，不能证明硬件原始计数；合成输入不能代替物理设备频率。

官方服务器标注 75Hz，200Hz 的接纳、转发/取最新/累计策略仍未知。鼠标字段物理单位未规定，
需要确认每周期增量解释在下游是否正确，尤其下游 75Hz 只取最新包时可能损失位移。
必须测量端到端延迟、持续运行和视频负载，不能将 5ms 发布周期当作最大控制延迟。
