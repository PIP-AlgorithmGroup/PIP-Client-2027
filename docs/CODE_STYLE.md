# PIP-Client 代码与工程规范

本文档是 PIP-Client 的正式代码规范。除非项目负责人明确批准例外，所有新增和修改内容都必须遵守本规范。

## 1. 文件与编码

- 使用 UTF-8 编码、LF 换行，文件末尾保留一个换行符。
- 缩进统一使用 4 个空格，禁止 Tab。
- 文件名使用小写字母、数字和下划线；Qt 类型名仍遵循 C++ 命名规范。
- 不提交构建目录、日志、缓存、生成物、密钥、令牌、个人路径或机器专用配置。
- 禁止依赖当前工作目录、盘符、用户名或开发机专有路径。

## 2. 格式与命名

- C++ 使用项目 `.clang-format`；Google 风格，最大行宽 100 列，大括号与控制语句同行，指针左对齐。
- 禁止为了格式化修改无关代码；提交前运行格式检查。
- C++ 类、结构体、枚举使用 `PascalCase`；方法使用 `camelCase`；局部变量和参数使用 `snake_case`；成员变量使用 `snake_case_`；常量使用 `kPascalCase`。
- Python 模块、函数和变量使用 `snake_case`；类使用 `PascalCase`；常量使用 `UPPER_SNAKE_CASE`。
- 布尔值使用 `is_`、`has_`、`should_`、`enable_` 等明确前缀；禁止 `tmp`、`data2`、`foo` 等无意义名称。

## 3. 注释与文档（强制）

注释是质量要求，不是可选装饰。每轮开发 session 在修改代码前必须读取本文档，并在结束前检查新增和修改代码的注释完整性。

- 所有公开类、结构体、枚举、函数、信号、属性和关键成员必须有 Doxygen 或等价注释。
- 复杂函数、状态转换、线程协作、资源生命周期、边界处理、协议解析和性能敏感逻辑必须有注释。
- 注释必须解释意图、约束、原因和调用契约，不能只重复代码表面含义。
- 涉及单位、坐标系、时间基准、精度、范围、所有权、生命周期和线程安全时必须明确写出。
- 修改行为、错误处理、生命周期或约束时，必须同步更新原有注释。
- 注释必须紧邻被说明的代码，且与实现保持一致；禁止过期、猜测或矛盾的注释。
- 简单、直观、没有额外约束的私有实现不强制添加重复性注释；非显然逻辑仍必须注释。
- 临时方案必须说明原因、限制和升级条件；禁止保留无责任人的 TODO/FIXME 或大段注释代码。
- 公开接口注释至少说明功能、参数、返回值、失败条件、副作用以及线程安全和生命周期要求（如适用）。

## 4. C++、Qt/QML、FFmpeg 与实时系统

- 类和函数保持单一职责；优先组合和依赖注入，避免单例及全局可变状态。
- 使用 RAII 管理文件、锁、线程、句柄、Qt 对象和 FFmpeg 资源。
- C++ 负责协议、设备、媒体、状态和业务逻辑；QML 负责展示、交互和视觉状态，不得承载复杂业务。
- 明确视频像素格式、色彩空间、分辨率、帧率、时间戳、时间基准、帧所有权和缓存上限。
- 网络 I/O 不得阻塞界面线程；协议实现必须校验长度、范围、版本、校验和超时，并处理非法、截断、重复、乱序和断线重连。
- 实时路径必须定义并验证延迟、帧率、丢帧率、CPU、内存和长期运行稳定性目标。

## 5. 资源、并发、配置与故障恢复

- 明确共享对象的线程安全边界、线程启动/停止/取消、`join` 和析构顺序；禁止数据竞争和悬空访问。
- 配置项必须有名称、类型、单位、默认值、范围和组合约束；解析失败不得继续使用部分有效数据。
- 日志必须包含事件、对象、状态和上下文；禁止记录密钥，高频路径禁止无控制输出。
- 网络、视频、配置和界面模块应有独立故障状态；单个模块故障应能降级，比赛模式禁止阻塞式调试窗口。

## 6. CMake、依赖、跨平台与测试

- 编译选项、头文件路径和链接库优先设置到具体 target；依赖固定版本或兼容范围并记录许可证。
- 平台差异集中在适配边界；路径使用 `std::filesystem` 或 Qt API；构建脚本必须能在干净环境执行。
- 测试覆盖正常、非法、边界、超时、失败恢复、资源释放、回放、压力、故障和实机环境。
- 一个提交只解决一个清晰问题；提交前检查差异、格式、静态检查、编译和相关测试。

## 7. 规范例外

例外必须记录违反的条款、必要原因、影响范围和重新评估条件。
