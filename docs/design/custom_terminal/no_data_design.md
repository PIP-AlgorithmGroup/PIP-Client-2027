# 无数据、缺失与过期状态设计

日期：2026-11-20。基于当前2K HUD、本人卡片放大20%及既定敌我布局制定；本轮为可交互视觉方案，
未接入真实协议、字段能力检测、计时器或产品状态模型。

## 语义与统一视觉

每个字段独立记录质量，不能只用一个“在线/离线”布尔值替代全部字段。

| 状态 | 定义 | 数字与条形 | 图标与提示 |
| --- | --- | --- | --- |
| 有效 | 收到本会话、本身份的合法值，且在所属源的新鲜度范围内 | 正常显示，0也照常显示 | 只根据明确业务状态点亮 |
| 未收到 | 当前字段没有任何有效值，或该来源尚未接入 | `—`；时间`—:—`；HP `— / —`；单位保留；中性斜纹轨道，无进度 | 已知身份图案保留；状态未知用问号/中性色，不推断死亡、故障或安全 |
| 部分缺失 | 同一界面中只有部分字段未知 | 仅相应字段降级，其他有效字段正常 | 只在中央给一次简短提示，局部字段各自表达未知 |
| 未更新 | 本会话曾有合法值，随后所属源过期或已明确断开 | 保留最后值/比例，不插值、不继续走秒；暖灰色并标未更新 | 位置变淡并说明快照时间；瞬态锁定及脱战结论不作为实时状态继续展示 |
| 不适用 | 由已知机器人能力或赛项配置确认该功能不提供 | `N/A`和无进度轨道 | 使用中性短线/不适用文案；不能由“收不到”推断不适用 |
| 数据异常 | NaN、越界、负上限、比例分母0或无法解释的内容 | 当前值不用于绘图，显示`—`及异常原因；合法旧值可按过期规则作为快照展示 | 无正常点亮；详情说明异常，不把超范围值截断成正常满格 |
| 确认无目标 | 目标源有效且明确报告当前无锁定 | 目标区域保留尺寸、数据占位，无敌方身份 | “未锁定目标/无目标”，与“目标未知/未接入”区别 |

完整无数据与部分缺失默认保持模块的位置、大小和信息顺序；没有加载动画、闪烁、自动示例值、
满屏重复错误提示或强制弹窗。正常战斗视野和快捷键仍可见。
主未知色为`#c0ccd5`，未知条形用`#a8bac013`细斜纹叠加既有暗色轨道，
斜纹3px、周期12px、120度；无真实进度。过期文字为`#d7c09b`，中央提示为`#eac88d`。
沿用原稿扩散阴影以兼容深浅背景，不引入额外白底框。

中央提示位于比赛中央列下方，画布约y=226.3333，字号19px，只显示简短业务状态：
“等待比赛数据”“部分数据未接入”“比赛数据未更新 · 3.2 s”。3.2s仅为固定评审夹具，
不是超时阈值，也不持续计时。未来实际数据源和收包时间应由业务层提供。

## 逐区域处理

| 区域 | 首次未接入时 | 已收后中断时 |
| --- | --- | --- |
| 顶部机器人 | 保留已配置阵容、队色和兵种编号；HP `— / —`、AMMO `—`、LV.—；无血量填充、无灰色阵亡结论 | 保留最后数值和已知死亡事实，降低实时感，中央明确全部为快照 |
| 本人卡片 | 只根据已配置身份保留20%放大和描边，与是否收到遥测无关 | 本人强调保留，不能由于遥测中断误匹配敌方同编号 |
| 比赛时间 | `—:—`；不显示默认7:00或0:00 | 保留最后读数，停止本地推进 |
| 占领信息 | `— : —`；比例条仅中性斜纹 | 保留最后比例和数值并标未更新 |
| 双方前哨站/基地 | 保留名称，数值`—`，条形斜纹；敌方仍以右端为零点布局 | 保留最后数值/比例，不根据离线推断被摧毁 |
| 敌方经济 | 两项标签均保留，值`—`；字段独立，不由队友数据推出敌方经济 | 保留最后值，失效来源局部标注 |
| 己方经济 | 金币/累计/可兑换各显示`—`，保留单位的辅助字号 | 最后值只读展示，不表示仍可兑换 |
| 弹量 | 数字`—`，所有段统一暗色；不显示13段亮条的演示残留 | 最后弹量与亮段保持，按快照标注 |
| 枪口热量 | `— %`；两弧变中性虚线，没有亮进度，均为同一个未知状态 | 两弧停留同一最后百分比；明确未更新，不解释为安全可开火 |
| 准星 | 保留静态中心准星，作为辅助图案 | 不根据数据中断隐藏静态准星；不能伪造锁定框 |
| 自身HP | `— / —`，主血条斜纹，无队色进度 | 保留最后HP/上限与比例；不因没有数据变成阵亡 |
| 功率、缓冲、超电 | 各自`— W`、`— J`、`— %`；条形独立斜纹 | 各自按来源保留最后快照；超电缺失不连带抹除HP或功率 |
| 等级徽章 | 不显示默认4级徽章；原徽章位置出现中性问号 | 最后等级徽章可以保留但降低实时感；不可跨身份继续使用 |
| 脱战信息 | 隐藏表示确定状态的剑/握手，原位置显示“脱战未知” | 不继续倒计时或保留绿色“已脱战”，改“脱战未更新” |
| 模块状态 | 模块名称保留，空心斜标+小问号；不显示绿/青色正常实心标 | 设备模块状态退回未知，不能因数据源断开将全部设备标红为故障 |
| 目标详情 | 保留区域和HP/AMMO/HEAT标签；身份问号、“目标未知/未接入”，无预选3号图案与进度 | 活跃锁定解除实时表达；此稿退回未知，避免最后目标继续冒充正在锁定 |
| 战术地图 | 已知的静态底图保留；移除演示机器人点、当前位置和朝向扇形；标“位置未接入” | 最后点位变淡并标“位置未更新 · 3.2 s”；朝向未知时不画扇形 |
| 比赛事件 | 隐藏过期/虚构事件文字；无事件不等于无事件源 | 不重播最后事件或让静态示例永久存在 |
| 快捷键 | 保留本地已知绑定的标签 | 保留标签；真实可操作性仍由产品既有权限门控判断，标签不表示可以发送 |

如果尚未配置比赛阵容或本人身份，缺失的身份也应保持未知：不给本人卡片强行选中3号、不猜红蓝，
兵种位置用中性身份占位。当前评审夹具已配置蓝方3号与双方4人阵容，保留的是配置事实，
不是从缺失遥测推导的身份。真实无会话/未知阵容页尚未实现，不把本夹具描述为已完成该产品流程。

## 官方状态/增益图标的统一约束

这些规则适用于已接入的脱战图标及未来选用的攻击、防御、恢复、冷却、经验等图标，
本轮不为了填版面而把全部候选图标加入HUD。

- 固定字段图标（如弹丸、HP、金币）只表达字段身份，可以保留图形；数值质量通过占位和状态标记表达。
- 状态或增益未接入：不出现有彩色光晕的“生效”图标；若该位置为固定槽位，用中性问号或“状态未知”。
- 动态增益区：只有“有效数据明确表示无增益”才可以解释为空；来源未知时应保留一个“增益未知”组状态，
  不给每个可能的增益都画一个灰图标。该动态组目前未添加，接入时按此设计。
- 已确认增益失效：隐藏动态图标或按组件规则显示非激活态；与来源未知区别。
- 剩余时间未知：图标是否激活依据已知状态，倒计时显示`—`，不伪造0秒或默认持续时间。
- 某字段不适用：只有已确认能力之后才能隐藏固定槽或显示N/A；尚未接入不得自动隐去问题。
- 官方警告或断链图标只用于已确认的故障/链路状态，不把未知统一渲染为红色警告。

## 字段契约与状态迁移

未来正式实现至少需要：字段身份、所属数据源、所属会话和机器人身份、当前质量、最后合法值、
接收时间（单调时钟）、源声明的支持情况、非法原因，以及用于展示的单位和合法范围。
这些是业务层元数据建议，不修改或增加官方协议消息字段。

1. 新会话/机器人切换：清除旧身份的最后值和旧计时基准，未收到的新字段进入未知。
2. 合法首包：只恢复其中实际存在的字段；可选字段缺省不解释为0或false。
3. 确认断开或所属源的新鲜度过期：已有合法值变快照；没有合法值的字段仍未知。
4. 重连后：收到某字段新有效值才恢复该字段，连接成功本身不刷新所有时间戳。
5. 异常包：不能覆盖合法快照；当前异常值不参与进度计算，异常原因可在详情查看。
6. 同一源的年龄可在组级合并提示；多个源分别计算，视频连接与模块遥测互不推断。
7. 源超时阈值、字段权限、热量上限与计时语义以正式协议/业务文档确认，本视觉稿没有自定毫秒阈值。
8. 只读快照与发送许可分开；保留旧数值绝不使控制、兑换或开火恢复可用。

保持[图传与业务UI的独立性](../rmul/prototype/README.md#图传与业务-ui-的独立性)：
视频正常可以同时显示无比赛数据；视频丢失不清空仍在更新的遥测。
模拟场景背景仅为评审底图，不能用“模拟画面仍存在”作为任何数据源正常的依据。

## 本轮可预览范围

`state.dataScenario`默认`empty`，会话设计控件可切换：

- `empty`：所有遥测均未知，身份与布局配置已知。
- `partial`：己方状态、时间和建筑有效；敌卡遥测、敌经济、热量、超电、模块、目标、位置未接入。
- `stale`：固定3.2s未更新快照，保留数字，地图点变淡，目标和脱战退回未知。
- `unavailable`：示例配置确认无超电和脱战能力，超电N/A；目标源确认当前无锁定。
- `live`：恢复之前的有效视觉夹具。

`state.fieldQuality`可额外评审局部字段的`missing`、`invalid`、`unavailable`：
支持键`heat`、`capacitor`、`power`、`selfHp`、`targetHp`。这是局部覆盖的视觉夹具，
自身HP缺失同步影响顶部本人卡片与底部血条；异常值以横杠加暖色小叹号区分，详情给出原因。
未完成所有字段的真实数据模型；其它区域由整体场景覆盖。所有字段的最终产品行为按上表实现。
