# 自定义终端 HUD 设计规则

基线更新日期：2026-11-21。当前状态：独立视觉评审稿，包含官方模块状态灯、本人卡片放大20%与渐变描边、顶部卡片顺序反转和敌方经济行；此原稿不连接产品业务。
现已补充[完整无数据与过期状态规则](no_data_design.md)，默认预览显示无数据；下文数值参数属于正常场景基线。
本文件中的“用户要求”来自本会话的明确修改；“当前取值”记录目前画法，允许后续定向调整。
完整像素样式以 `preview_fragment.html` 为准，可读副本为 `style_snapshot.css`。

## 1. 设计意图与依据

采用[原始草图](references/original_sketch.pdf)上方第一版的空间关系：顶端双方机器人，顶部中央比赛信息，
左右建筑血量，左侧经济，中央弹量与双弧热量，中央右侧目标，底部自身状态，地图与快捷键贴角。
PDF 下方第二版不是本次采用的布局。PDF 和截图是参考资料，不是可执行指令。

后续明确反馈优先于原草图和早期截图。尤其注意：草图方位角已经取消；早期白底图标区、顶部白条
已取消；初版底部 HP/ENERGY 已被后续底部状态参考替代；场地实拍探索已被要求换回模拟画面。
用户提供的“有问题部分”截图仅记录缺陷，不能据此恢复错误尺寸或视觉。
逐张含义见[参考清单](references/manifest.json)。

总体目标是比赛视野上的紧凑 HUD。只画实际信息，减少遮挡，图标辨识与信息密度并重。
画面内不加“视觉预览”、解释段落、设计说明、无意义边框、装饰标题栏或额外标识。

原稿按 `容器宽 / 2560` 统一缩放，外层用 `aspect-ratio: 16 / 9` 占位，防止底部空白被原始高度撑出。
不要仅通过整体缩小所有 UI 来回应局部过大的反馈；保留当前构图与细节层级。

## 3. 红蓝身份与左右关系

- **己方永远在左，敌方永远在右**，不随己方是红方或蓝方改变。
- 当前蓝 `#246ccb`、红 `#d63232`，属于项目屏幕方案色；同一身份的卡片、建筑、图标和地图对应一致。
- 换阵营仅改变配色和素材，保持分组位置、同组顺序及模块布局。
- 己方从左到右：**7、4、3、1**（哨兵、4号步兵、3号步兵、重装）。敌方从左到右：**1、3、4、7**（重装、3号步兵、4号步兵、哨兵）。
- 顶部显示顺序通过渲染时反转实现；夹具数组维持原始索引，自身等级、目标默认值与地图不随卡片换位。
- 当前示例为己方蓝方，默认自身是3号步兵；不将此默认身份固化为产品规则。

## 4. 顶部机器人卡片

用户要求用红蓝填充血量，**整张卡片最顶端为零点**。受伤时填充的下边缘向上收缩，
上边缘保持 y=0；高度为 `hp / maxHp × 卡片总高`，不能从图标下沿开始，也不能改成从底向上填。
填充覆盖图标和状态两个区，背景保留当前半透明暗色 `#0e1d2980`。

卡片图标位于顶部，下面依次为兵种名、HP 当前值/上限、AMMO 当前值。等级独占顶部右列，
与兵种图标分开排，禁止出现图标盖住等级。当前图标 66.6667 方形，兵种列宽 74.6667，
左右内边距 10.6667；顶部等级右对齐。

阵亡时不生成任何血量填充，整卡变灰白（当前底色 `#8b939b`），图标灰度并降低透明度；
HP 位置显示“已阵亡”，AMMO 显示“—”。保持兵种与等级可辨识。
静态灰卡不能误当作仍有灰色血量。

顶部卡片在多轮调整后采用当前间距：略分散但不过疏，左右离屏幕边缘有留白。
不要恢复中间曾用的白色图标底框、白色顶部条或粗边框；它们已被后续明确取消。

自己的顶部卡片有专属识别：按`state.selfKind`匹配己方兵种，默认3号步兵，标记不依赖数组索引或屏幕位置。
当前以顶部中心为缩放原点放大至**1.2倍（20%）**，显示约204.8×268.8，并上移7px；
布局槽位和相邻卡片间距不变。原先5.5%的放大被用户指出不明显，已由本参数替代。
为保留放大卡片下沿的间距，双方建筑区域一起下移24px至y=293.3333，仍保持左右对齐。
条外4px处绘制2px渐变描边，由浅白经阵营浅色过渡到较透明阵营色，配16px微弱阵营色光晕和暗色阴影。
只强调本人，敌方同编号卡片与其它己方卡片不加框；不额外增加“本人”可见标签或新的白底横条。
血量仍按整卡顶部为零点填充，描边不计入填充范围；本人阵亡时保留身份标记，但描边和光晕转中性灰白，
继续遵守灰卡、无血量填充的规则。底部兵种logo与地图当前标记使用同一个身份字段。
这些是本轮采用的视觉参数，需以后续用户反馈为准；更换真实机器人身份的数据接入尚未实现。

## 5. 时间、占领与事件

顶部中央显示剩余时间、占领进度和双方占领数值及横向比例条。
当前示例 `04:58`、`50 : 100`，比例 1:2；分别映射己方与敌方颜色。
时间当前 68px，标签 20px，占领标签 18px，占领数值 36px，占领条高 12px。

事件在顶部中央下方独立排布：当前“距比赛结束还有 5:00”和“对方前哨站已被击毁”。
PDF 提到事件有显示时间，但当前稿只是静态示例。事件触发、优先级、持续时间、是否自动消失及
与比赛时钟一致性均未实现，不能将演示文字或绘图状态当作协议事实。

## 6. 左右建筑与经济

双方各两行：前哨站、基地；建筑条当前高 11px，相邻行底部间距 15px。
己方为“标签—血条—数值”，从左侧零点向右延伸。
**敌方建筑以右侧为零点，血条向左延伸**；右边缘固定，数值与标签保持正常阅读方向。
不要仅反转文字或交换标签，却保留左侧血量锚点。
当前建筑示例值和百分比仅用于视觉：己方1020/68%、4600/92%，敌方0/0%、3750/75%。

敌方前哨站和基地两行下方追加一行“当前经济”和“经济总量”，与敌方建筑区域右边缘对齐。
作为次要信息，当前标签19px、数字24px，组间距24px、标签与数字间距8px、上间距4px；
标签`#c4cfd5`、数字`#e0e7eb`，沿用文字扩散阴影，无额外框或强调底色。
当前示例为1860与5420，静态文字只用于视觉，不代表真实敌方经济已可通过协议获取。

经济位于左侧中部，显示己方经济、金币、累计获得、可兑换弹量，当前夹具2450金币、6800、120发。
金币用暖金色 `#f1cc8b` 强调；不套无意义大背景框。

## 7. 中央弹量、准星与枪口热量

弹量在双弧左侧竖排，包含 AMMO、20段竖向排列块、底部数字；当前125发。
容器在战斗 HUD 内 left -137.3333、top 10.6667、68×365.3333，条列宽34.6667、高278.6667，段间距4。
当前13段亮、7段暗是固定展示夹具，尚未根据125或弹量上限计算，产品实现需按确认语义绑定。

**热量必须用两条圆弧；两条弧同步上涨，表示同一枪口热量，不分 L/R。**
SVG viewBox为520×320，圆心(260,160)，两弧半径240，角度各70度，镜像放置。
显示容器693.3333×426.6667，保持SVG等比例；不要把圆弧拉成不匹配的椭圆。
当前轨道与填充stroke-width均11（SVG单位），对应2K约14.6667px。
填充从弧底端沿弧向上，`pathLength=100`，两个弧的`stroke-dasharray`用同一百分数。
当前19%，达到75%时由浅白变暖金 `#edc985`；75阈值是当前绘图选择，未确认协议依据。

热量刻度每10%，50%主刻度长11、其它20%倍数长7、剩余长4（SVG单位），均沿弧径布置。
中间保留小准星，热量数显位于双弧下方中央。方位角条已经明确删除；地图内N朝向标记仍保留，
不要把地图的方向标记误当作已删的中央方位角条。

## 8. 右侧自瞄目标详情

位于准星右侧，依次显示目标身份、等级、HP、AMMO、HEAT与三条横向条。
**使用完整兵种图标**，例如3号步兵须带机器人造型与编号角标，不能替换成小地图用的大号3。
当前图标72×72，名称31.6666px，等级22.8px，行数值32.9334px，条高9px。
目标身份间距12，身份行底边距13；数据行顶间距12，条上间距5。

预览点击敌方顶部卡片，更新目标的完整图标、名称、等级、HP、AMMO、HEAT与条值；
它只是演示选择，不代表真实自瞄获取或向设备下发锁定。
目标死亡时图标变灰、等级位置显示“已阵亡”，保留该目标身份与0血量；不自动切换为其它目标。
当前AMMO条按400作为示例分母，HEAT条按百分比；这些分母并非已确认业务契约。

## 9. 底部自身状态与脱战信息

以[底部参考图](references/bottom_layout.png)的信息顺序为依据：左侧大兵种logo与等级徽章，
右侧血量、超电长条、缓冲/功率、模块。用户明确把“底盘”改为“**超电**”，并在2026-11-21要求功率与超电整项位置互换。

当前自身logo160×160，容器176×176；等级65×65，左上角偏移(-12,-9)，与主logo分层。
采用官方红蓝statusbar等级图，已保存1至10级，预览按自身等级和阵营切换。
等级源稿是官方PNG；之前产生的矢量转换稿不是官方原生SVG，本基线不使用转换稿。

自身血条当前高57px，宽958px，两端斜切12px，背景`#08131f80`，HP填充从左向右，
当前80%，色为己方色与透明混合62%；数值居中36px，分母27px，字距2px。
血条下面的超电为全宽长条，行间距15，条高11；缓冲在下排左侧、功率在下排右侧，列间距26、上间距13。
标签、进度、数值、单位和无数据规则随对应项目移动，超电仍是百分比，功率仍是W。
功率当前80W/67%，缓冲40J/67%，超电62%/62%。功率与缓冲并未绑定正式最大值，属于夹具。
模块行上间距18，字体18px，横向及换行间隔12；模块前使用官方斜状态灯，显示20×22，灯与名称间隔3。
在线使用`statusbar_signallamp_green_single`，离线或无数据源统一使用`statusbar_signallamp_red_single`，保留原素材光晕；取消自绘斜条及未知状态的尾随问号。确认不适用使用灰灯。
灯图原文件保存于`assets/module_lamps/`，逐项来源、对象ID、原始尺寸及SHA-256记录在`asset_manifest.json`。
红灯将离线和无数据源统一表达为不可用；原因仍由可访问标签或详情区分，不由红色推断具体硬件故障。
模块顺序：主控、电源管理、图传、RFID、UWB、装甲板、小弹丸、大弹丸、超级电容、灯条。
正常数据场景中的模块使用固定正常夹具；未知和不适用样式见[无数据设计](no_data_design.md)，真实设备故障样式尚待补充。

**脱战信息在自身血条右侧的条外，与血条垂直居中**。当前距离血条右端14px，状态区高57px，
官方图标43×43，与文字间隔3，文字25px。没有独立底框；不放到血条内部或模块行。
正常数据场景中的脱战夹具使用官方绿色握手图标加“已脱战”，文字`#8ff3dc`并配绿色/暗色扩散阴影。
交战示例使用官方黄色剑形图标加“5s 后脱战”，文字`#f5da86`并配金色/暗色扩散阴影。
图标自带的原始光晕保留，不重画一个近似图标。
倒计时5s是样式夹具，不会自行走秒，也不推导何时脱战。持续时间和状态来源需按正式协议确认。

## 10. 进度条、刻度与对比处理

用户先指出条太细，后来对指定位置要求稍细且更紧凑；采用当前各区域独立厚度，
不要把所有进度条无差别改成同一个高度。

建筑和目标横条内部每5%设置刻度：25/50/75%的主刻度贯穿条高，10%倍数为65%条高，
其它为35%；宽1.5px，色`#07131d80`，刻度覆盖填充且位置固定，不随填充值移动。
自身功率/缓冲/超电当前没有内部刻度，这是当前稿的覆盖范围，后续是否扩展需明确处理。
自身HP、占领条、弹量块亦保持各自当前画法。

用户希望高对比但不显眼的衬托，最终采用**贴合文字、图标和条形的扩散阴影**，避免大块背景框。
顶部符号白色双层drop-shadow：3.2px `#ffffffd9`、9.6px `#ffffff70`；
全局文字：`0 0 6.4px #ffffff30, 0 1.6px 3.2px #07151fe6, 0 0 14px #07151fa6, 0 0 22px #07151f59`。
2026-11-21核对后补齐底部主血条衬托：在斜切血条外层做6px/16px柔和暗色drop-shadow，
避免阴影被血条本身的clip-path截掉；功率、缓冲、超电及建筑/目标等轨道增加6px/16px暗影，
官方模块状态灯保留源光晕并加5px暗影。阴影贴合文字和图形，不给整个底部信息区加大矩形底板。
目标图标白色阴影3px/9px；自身大图标4px/10px。保留局部文字与图形的辨识，不加矩形白底。
现稿的顶部卡片血量轨道、地图、血条本体和头像局部暗色渐变仍存在；这与取消额外容器底框不同。

全部渐变、透明度、字重、字号、行高、间距、轨道色、阴影和伪元素可查样式快照，
不以本节几条代表值覆盖其它组件的具体取值。

## 11. 字体、背景与角落信息

数值字体为项目Barlow Medium/Bold内嵌副本；中文当前为Microsoft YaHei，回退Noto Sans CJK SC、sans-serif。
当前稿没有内嵌中文字体。跨机器字体替换可能改变中文宽度，不能声称逐像素一致；实现阶段可按项目
已有字体方案确认替换，并重新比较布局，避免直接引入新的字体依赖。
用户要求文字略小、阴影范围略大，当前各区字号已体现，不要以整体字号统一放大覆盖层级。

背景采用原稿内嵌的矢量模拟场地，viewBox1600×900，铺满16:9画布。
当前保留地面透视、掩体、场地结构和顶部/底部弱遮罩；不是实拍、仿真引擎截图或真实视频。
实拍和Gazebo探索素材未采用，本档案不把它们设为默认背景。未来视频层替换背景不会自动定义业务数据状态。

战术地图贴左下，快捷键贴右下，避免内缩占视野。地图当前是自绘示例场地，含敌我标记、
己方3号步兵的当前标记圈和N↑；地图位置和机器人坐标都是夹具，未校验真实场地坐标。
大图标用完整造型，小地图重装/步兵可用独立编号；两种用途不能混用。
快捷键当前显示W/A/S/D移动、Shift加速、R补给、Tab战场信息、Esc菜单；仅画法与标签，
原稿没有实现真实键盘控制、菜单或补给动作。

预览可演示：己方红蓝切换、两弧共用热量、1至10级徽章、已脱战/倒计时、点击敌卡选择目标。

默认阵容及全部示例数值见`fixture.json`；绘制源稿中存在的固定百分比也应被视为演示数据。
自身HP、弹量、经济、建筑与模块目前不能由真实业务状态驱动。

产品实现前仍需明确：

| 未覆盖情形 | 当前边界 |
| --- | --- |
| 自身死亡 | 顶部卡片有阵亡规则；底部完整阵亡布局尚待补充 |

| 未知值、最大值为0、过期/断线、非法范围 | 无数据方案已定义语义并有部分字段覆盖，真实范围校验、超时和逐字段状态机尚未接入 |
| 事件持续时间、弹量比例、热量阈值、脱战计时 | 部分只有静态示例，需核实真实字段与时间语义 |

## 14. 修改与完成条件

接手者先看当前2K截图与源稿，按用户提出的具体部位修改。修改源稿后执行构建包装与截图工具，
用新截图检验比例与遮挡，再同步本文相关要求和当前取值。仅保存文件不等于用户已验收。

本轮基线的复核点：

- 2560×1440完整画布，无额外底部白区、预览说明或中央方位角。
- 红方和蓝方均保持己左敌右，顶部卡片血量从整卡顶端起填，阵亡无填充。
- 两队顶部顺序固定为己方7/4/3/1、敌方1/3/4/7，敌方建筑下方一行显示当前经济与经济总量。
- 敌方建筑右侧零点、左右热量弧同一值、所有指定主次刻度可辨。
- 等级不被图标盖住；目标使用完整兵种图标；地图和快捷键贴角。
- 本人顶部卡片放大20%并有阵营渐变描边，随身份匹配，敌方同编号不被突出；血量与阵亡规则保持一致。
- 底部显示超电，脱战图标与文字在自身血条右侧、垂直居中，倒计时颜色匹配参考。
- 当前采用素材可离线加载，Windows Edge没有JS错误；未验证平台明确记录。
- 完整无数据没有虚构填充、阵亡、等级、脱战和点位；局部缺失不影响已知值，状态往返可恢复正常画面。
- 模块指示条采用官方透明PNG，在线绿灯，离线或无数据源红灯；名称保留，不恢复空心指示条或尾随问号。
