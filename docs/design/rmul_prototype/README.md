# RMUL 视觉评审原型

问题：明亮中性灰、橙色强调的赛事终端方向，能否统一无信号主页面与 ESC 会话页？
本轮按已选方向制作两张关联界面，没有增加互不相关的三套风格。
这是独立评审稿，不是正式 QML，不调用裁判系统、系统设备或真实配置存储。

## 查看

直接用浏览器打开本目录 `index.html`，或在仓库根目录执行：

```sh
node docs/design/rmul_prototype/serve_preview.cjs
```

打开命令输出的本机地址。服务仅绑定 127.0.0.1，Ctrl+C 退出。
`?view=waiting` 查看无信号主页面，`?view=session` 查看当前会话。
底部“设计预览”工具条切换页面、UI 档位和四种图传状态；Esc 开关菜单。
URL 增加 `&capture=1` 可以隐藏评审工具条。

机器人预选蓝方步兵 3 号仅为示例；切换阵营清空兵种，选择后联动 ID。
其他设置分类此轮只保留位置与导航入口，返回欢迎页和保存按钮只显示预览提示。
所有展示的接收、网卡和 MQTT 状态都是示例，不是运行中的客户端检测结果。

## 设计参数

| 项目 | 本轮方案 |
| --- | --- |
| 主强调色 | `#c94b17`，用于主动作、选中与焦点，属于项目方案 |
| 主文字 / 辅助文字 | `#24272b` / `#62666e`，正文与背景保持明确对比 |
| 菜单 / 侧栏 | `#fafafa` / `#edeef0`；侧栏、分组和操作栏采用细分隔线 |
| 控件 / 菜单圆角 | 3 / 5 逻辑像素 |
| 字体 | 沿用已打包 Noto Sans SC 做版式预览；尚未确认赛事指定字体清单符合性 |
| 标题 / 正文 | 会话标题 24、无信号标题 24、输入正文 14 逻辑像素，中档 |
| 菜单 | 最大宽 1120、高 740 逻辑像素；按视口收敛，字号不随窗口缩放 |
| 阵营 / 状态 | 红蓝只用于身份；可用状态用绿色，其余状态配明确文字 |

视频层保持等比居中，没有 Logo、模式名、端点或角落菜单常驻装饰；监听信息放入 ESC。
无信号占位仅居中显示小图标、当前原因和菜单入口，不模拟比赛实况。未来业务 UI 是独立叠层，
其存在不依赖是否收到视频；本轮仍未设计或加入血量、准星等具体业务元素。
本原型未使用官方 Logo 或新 KV，不将设计颜色、几何或自绘图标称作官方标准。
字体及素材证据边界见[来源审查](../rmul_visual_reference_audit.md)。

## 图传与业务 UI 的独立性

原型使用同级的 `video-layer` 与 `business-overlay`，ESC 菜单覆盖于两者上方。
业务层按窗口坐标和 UI 档位布局，不作为视频纹理的一部分，也不随视频宽高比缩放。
图传占位只负责当前视频状态，不能隐藏、重建业务层或清除其中的数据。

后续正式实现遵守以下数据契约；它们是设计要求，本原型没有实际 MQTT 或业务状态模型。

| 情况 | 图传层 | 业务 UI |
| --- | --- | --- |
| 仅视频中断，业务数据仍到达 | 显示无信号占位 | 保持绘制，继续更新业务数据 |
| 业务数据源停止更新，视频仍正常 | 继续显示视频 | 保留该数据源的最后有效值，标记未更新；不伪造新数值 |
| 两条链路都中断 | 显示无信号占位 | 保留最后有效值及未更新状态 |
| 从未收到某字段 | 不影响图传 | 显示未知，不能用默认 0 冒充已收到的数据 |
| 更换机器人身份或比赛会话 | 由新会话管理图传 | 旧身份数据失效，不作为新身份的最后值继续显示 |

新鲜度应由各业务数据源的最后更新时间与接收状态判断，不能由视频状态推断。
图传恢复只替换视频内容，不重置业务叠层。未来收到业务新数据才更新对应显示；
不能把裁判系统业务数据或操作许可冻结规则与图传占位混在一起。
当前正式 `DataPipeline` 的 MQTT 失联清理语义尚未改造；保留只读展示快照应在后续业务状态层实现，
与控制发送、可操作状态和协议接收缓存分离。本轮不改变控制门控或后台链路。

## 预览与验证

- `waiting_1280x720.png`、`session_1280x720.png`：720p 对照。
- `waiting_1920x1080.png`、`session_1920x1080.png`：1080p 对照。
- `waiting_1024x640.png`、`session_1024x640.png`：最小窗口检查，小窗口/大档允许内部滚动，底部操作常驻。
- `validation.json`：字体加载、字号固定、水平溢出和交互检查记录；四种图传状态下独立叠层夹具持续绘制且未被清除。

复现截图需本地 Node.js、Playwright 和 Edge，执行 `node docs/design/rmul_prototype/render_preview.cjs`。
可通过 `NODE_PATH` 提供现有 Playwright，`PREVIEW_BROWSER` 切换已安装的浏览器通道。
此渲染工具不加入产品 CMake 或运行依赖。
当前只验证 Windows Edge 原型，尚未验收正式 Qt 渲染、Ubuntu、DPI 与硬件组合。
原型保存在 `codex/rmul-visual-prototype` 分支，后续选定后按正式 QML 约束实现。
