# RMUL 视觉参考来源核查

核查日期：2026-11-12。本文记录官方来源及其已核实的适用范围，不把设计偏好写成赛事硬性要求。
本轮核查公开资料、用户本机官方 PDF 和现有实现，没有修改产品代码，也没有完成 RMUL 2027 视觉合规验收。

## 审查结论

当前 RMUL 的设计记录以 QGroundControl、Mission Planner 和 OBS 的功能层级为参考，
见[原设计调研](video_receiver_research.md)，尚未建立 RoboMaster 官方界面参考与实现的逐项对照。
因此不应继续在现有样式上零散微调，也不能声称现有实现已经符合 RMUL 官方视觉规范。
本轮找到的明确客户端公告是 2026 RMUC 字体规范；其适用赛事和赛季必须保留。
字体包失效及 2027 RMUL 对应原文未取得，是本轮仍未解决的证据缺口，不是已证明违规的结论。

## 已核实的客户端字体规范

官方公告：[RoboMaster 2026 机甲大师超级对抗赛自定义客户端字体使用规范](https://www.robomaster.com/zh-CN/resource/pages/announcement/1896)，发布日期 2025-12-26。

- “一、适用范围”明确指向 **2026 年超级对抗赛 RMUC**，覆盖比赛目的客户端在现场、直播、录播及官方渠道露出的全部 UI 视觉元素，包括标签、按钮、Logo、菜单、对话框和图表文本。
- “二、UI 界面字体来源规范”要求使用附录指定的开源字体；不能仅凭字体是开源的，就认定符合该公告。
- 完全原创字体的例外要求保留设计源文件和创作留痕；禁止对现有字体调整笔画、字宽等二创修改。
- “三、UI 界面字体使用规范”要求保持字体文件完整性，允许使用官方文件中包含的不同字重和样式。
- 附录列出的 iconpark、icons、ikonate 是**参考网站**；公告明确它们与组委会无关联，实际图标仍须原创或无版权争议。

公告附录字体包为 <https://pan-sec.djicorp.com/s/iqp5byJWP9BJWgc>。本轮浏览器打开后跳转至 Tardis 文件通道，页面显示“文件未找到”“可能此共享已被删除或过期”。因此未能核对包内字体，不能确认项目的 Noto Sans SC、Barlow 是否位于指定包中。

**适用性边界**：上述公告能证明 2026 RMUC 有明确字体清单要求，不能未经 2027/RMUL 原文确认便断言其直接约束 RMUL 2027。当前未获取到 RMUL 2027 专门的同类公告。

Logo 目录包含基础 Logo、26 赛季 Logo、赛徽；基础 Logo 内含白色、灰色、异形和 AI 源文件。目录名称说明了素材种类，不能证明存在统一的客户端配色、按钮圆角或布局标准。本轮未下载或嵌入这些素材。

## 改造优先顺序

1. 固定引用版本和适用赛事，取得用户所指视觉参考原件；恢复官方指定字体清单的可核对来源。
2. 先核查终端展示内容、字体与素材授权，避免先大改视觉后才发现引用对象错误。
3. 建立共同视觉参数：字体/字重、文本层级、可读性、间距、边框、状态色、图标线宽；把待确认值标为项目方案。
4. 同一套参数覆盖 RMUL 视频待机页、ESC 菜单、会话/图传/显示/诊断页面，先做真实窗口尺寸对照稿，再分组件替换。
5. 保持现有交互约束：视频保持比例；UI 大中小档与窗口尺寸解耦，位置自适应；不向比赛主视频堆加未授权业务 UI。

## 对项目审查的直接影响

1. 应先明确用户所指参考文件的名称、版本及适用范围，再做逐条差异表。
2. 字体“有开源许可”和“列入赛事指定包”是两项不同检查；当前只能确认项目已有许可文件，指定包符合性仍待核对。
3. 品牌标识素材、赛季 KV、官方客户端截图可以作为不同层次的来源，但不能互相替代：素材授权、赛事规则和界面参考分别核实。
4. 在原文未取得前，可以提出视觉整改草案，但不能宣称已按 RMUL 2027 官方视觉规范整改完成。
