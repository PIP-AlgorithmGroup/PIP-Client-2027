# 平台与硬件兼容约束

本文是平台、后端依赖和硬件适配的强制设计约束。兼容目标与验证结果必须分开记录。

## 系统与依赖

- Windows 与 Ubuntu 为同等目标平台，核心通信、状态、控制和界面保持一致的业务行为。
- 选型前确认依赖在两套系统上的版本、编译器 ABI、许可证、驱动、部署和维护情况。
  单平台优化集中在适配边界，另一平台必须有可用实现或明确的功能降级。
- 使用统一 CMake 工程管理依赖与可选后端，平台 SDK、厂商 SDK 和系统句柄不进入业务层或 QML。
  根据实际差异建立适配，避免为未实现的能力创建空抽象。
- 按双平台行为设计路径、大小写、编码、动态库加载、线程、时钟、网络和资源释放。
  机器专用路径仅写入未提交的本地配置，各平台分别生成二进制产物。
- 发布时明确 Windows/Ubuntu 版本、CPU 架构、编译器、最低驱动和显示环境；
  Ubuntu 记录 X11/Wayland 的适用与验证情况，未验证组合不能标记为已支持。

## 目标硬件矩阵

下表是必须纳入后续设计和验证的设备类型，不表示当前已完成适配。
Core i 与 Core Ultra 跨越多个代际，不能仅按产品系列名推断实际能力。

| 设备类型 | 图形与视频路径 | 模型推理路径 |
| --- | --- | --- |
| Intel Core i 系列核显 | 按实际核显、驱动和编解码能力选择后端 | CPU 基础路径；满足条件时使用 Intel GPU |
| Intel Core Ultra 核显 | 探测实际 GPU API、格式及共享内存能力 | CPU/GPU 路径；确有可用 NPU 时增加 NPU 路径 |
| 配备 Intel NPU 的设备 | NPU 不承担 3D 图形渲染 | 按系统、驱动、运行时、模型算子和精度验证 |
| 配备 NVIDIA 独显的设备 | 支持核显/独显选择，考虑混合显卡的数据传输 | 适用时使用 NVIDIA 加速，同时保留无 NVIDIA 时的可用路径 |
| 缺少可用硬件加速的环境 | 保留基础界面，必要时停用可选 3D 或降低视频规格 | CPU 降级或显式停用可选推理，报告性能限制 |

## 渲染、视频与推理

- 3D 通过跨平台渲染层对接硬件，评估 Qt 图形抽象及系统后端。
  Direct3D、Vulkan、OpenGL 等按系统、设备和驱动能力启用。
  核显必须纳入资源预算，独显不能成为基础界面的启动条件。
- 推理通过明确的模型输入/输出契约与业务解耦，记录预处理、张量布局、精度与输出语义。
  ONNX Runtime、OpenVINO、NVIDIA 后端等均为待评估选项，按模型与平台验证后选型；
  支持某种模型格式不代表所有 GPU/NPU 都可运行该模型。
- CUDA/TensorRT 等厂商专用加速作为可选能力；CPU、Intel GPU、Intel NPU 与 NVIDIA GPU
  的可用组合由运行时探测和模型验证决定，不预设所有设备使用同一个执行后端。
- 验证模型转换、动态形状、算子覆盖、量化、缓存和运行时版本的兼容边界。
  切换后端需验证输出正确性与允许误差，不能静默改变精度或预处理。
- 视频解码、3D 与推理分别选择设备和后端，明确设备标识、纹理/张量格式、内存所有权与同步。
  跨设备共享与零拷贝须验证；无法共享时使用有界复制路径并测量复制开销。

## 能力探测与降级

- 运行时枚举实际设备，检查驱动、API、运行库和模型加载结果，区分设备存在与工作负载可运行。
- 提供自动选择及显式指定后端/设备的能力；选择结果、失败原因、实际回退和性能限制可诊断。
- 加速初始化失败、设备丢失、驱动重置或显存不足时，按模块契约重建、切换或停用可选功能。
  处理旧帧、未完成推理及资源释放，保持通信与控制链路可用。
- 保留可用的 CPU 基础路径，不承诺其达到硬件加速的实时指标；
  达不到预算时明确降低刷新率、分辨率或推理频率，必要时关闭可选模块。

## 效率与验收

- 实现实时模块前规定可测量预算：端到端延迟、帧率/吞吐、CPU、内存、
  GPU/共享内存/显存占用及持续运行稳定性；具体数值随功能和目标设备确定。
- 验证视频、渲染和推理并发时对内存、功耗和带宽的竞争，尤其是核显与 CPU/NPU 的共享资源。
  使用有界队列、异步调度和明确丢帧策略，避免加速任务阻塞 GUI 与比赛通信。
- 合入平台相关模块前执行 Windows/Ubuntu 构建、相关测试与部署检查。
  环境不足时记录未验证项，单平台通过不能视为双平台通过。
- 发布前在声明支持的系统与硬件组合上验证功能、数值正确性、性能和长期运行，
  覆盖没有 NPU/独显、后端不可用、混合显卡、驱动异常和回退情形。
  记录硬件、系统、驱动、运行库、模型、后端、参数和测量结果。
- 通用逻辑可用自动化测试和模拟故障验证；GPU/NPU、驱动互操作和设备丢失恢复须实机验证。
  加速缺失时跳过的测试必须可见，不能作为该后端已验证的证据。
